# Security

`cobalt-capabilities` is off after installation. Enabled, it adds privileged behaviour: loopback HTTP to a memory service, a loopback control connection to a browser, a loopback egress proxy, and two local worker processes (`python3 -I -B bridge.py`, which may run `node browser.mjs`). Workers are started by argument vector with a scrubbed environment, never through a shell.

**Authority.** The companion's tools ask Claude Code's own permission check and proceed only on `allow`; `ask`, `deny` and any error refuse before a worker, a configuration file or a service is touched. They install no permission hook, approve nothing, spawn no agent, change no model routing and pass no verification gate. An agent may use them only while it holds an admitted exclusive write task; unknown or malformed ownership state refuses. One lock serializes operations across local sessions.

**Untrusted content.** Recalled memory, reflections and page or console text are returned as data marked untrusted, never as instructions and never as verification. A retain is stored as verified only when the commander itself makes it and names a delegated task that the host observed to its end and the commander then verified; a helper of any tier, or a task the commander merely declared, yields an `agent_asserted` record. Memory written to the service by anything else is reported `unverified`. "Verified" records what the commander did in that session; it is not proof, and recall says so.

**Memory.** Used only in the working trees the operator names. The bank is a hash of the repository's own Git identity, a label rather than access control: the memory service is unauthenticated, so bind it to loopback and do not share it. There is no bank deletion, no transcript or file ingestion, and deletion is one companion-written document at a time. The adapter runs `git` with hooks and the file-system monitor disabled and does not let `git status` run a filter program the repository configures.

**Browser egress.** On the supported engine, request interception is advisory: a redirect hop, a parser-inserted resource and a scripted navigation were measured reaching a forbidden origin after interception refused them. The origin policy is therefore enforced by the companion's own egress proxy, which the browser must be started behind. Every request is checked there before any connection is opened: exact allowlisted origins only, `GET`/`HEAD`, no credentials, at the address the policy resolved and vetted for that request (private, link-local, metadata and reserved ranges refused, so a second DNS answer is never used). `CONNECT` is tunnelled only to an allowlisted `https` origin and upgrades are refused. Each task first proves the browser is routed through the proxy and has no route around it; a browser that cannot prove it is refused before it navigates, and there is no fallback to detection after the fact. A page the proxy answered is never reported as evidence of the site.

**What the proxy does not do.** It cannot inspect the inside of an `https` tunnel, so for `https` origins the method and header rules rest on interception. A `GET` can change a server. And it constrains what the engine asks for, not a compromised engine: Obscura is not a sandbox against native exploitation, so the browser must also run confined at the operating-system level, with the proxy port as its only route out. The [README](README.md) gives the tested launch and what was measured from inside it. Personal browser profiles, host secrets, stealth builds and any other proxy are unsupported.

**Local machine.** Loopback ports are reachable by every local user, and neither local service's identity is verified beyond its address. On a shared machine another user could make a browser task fail, use the proxy to reach your allowlisted origins during a task, or impersonate the memory service. Run the companion on a single-user machine.

Secret filtering is heuristic. A retain that times out may have been stored; the result says the outcome is unknown. A failed browser task names the steps that may already have had an effect. See [docs/architecture.md](docs/architecture.md) for the design and [docs/release-v0.1.0.md](docs/release-v0.1.0.md) for what was tested.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting for this repository if available. Otherwise contact the repository maintainer through their GitHub profile to arrange a private channel. Do not post secrets, private memory contents or exploit details in a public issue. Include the affected version, a minimal synthetic reproduction and the expected impact.
